# Estrategia SEO de moiraordo.es

Plan de cobertura de búsquedas: qué términos usarán los clientes potenciales, en qué páginas los cubrimos y qué falta. Complementa [guia-seo.md](./guia-seo.md) (alta en buscadores) y [seo-ia.md](./seo-ia.md) (la misma estrategia para asistentes de IA).

> **Importante.** No hay datos de volumen de búsqueda en este documento: no se ha usado ninguna herramienta de pago ni se ha consultado Search Console (la web aún no tiene histórico). Los términos son hipótesis basadas en cómo se busca este tipo de servicio en español. El primer paso tras publicar es **validarlos** con Google Search Console (consultas reales), el Planificador de palabras clave de Google Ads y, si hay presupuesto, Ahrefs o Semrush. Hasta entonces, la prioridad es ordinal (alta/media/baja), no numérica.

## 1. Objetivos

1. **Captar a quien ya sabe lo que busca** («diseño web a medida», «web para inmobiliaria») con páginas de servicio y de sector.
2. **Captar a quien está investigando** («cuánto cuesta una página web», «qué es un CRM») con guías.
3. **Ser el estudio de referencia en tres sectores** donde hay casos reales: inmobiliarias, reformas y transfers/VTC.
4. **Posicionar la marca y sus productos**: Moira Ordo, Moira Ordo Games, MusiBingo, MatchRise.
5. **Ser citable por asistentes de IA** (ver [seo-ia.md](./seo-ia.md)).

### 3.7 Decisión pendiente: servicio de SEO y publicidad

La web promete «nos encargamos de tu SEO y publicidad» y los casos de Arquelia y Reformas Llobregat incluyen marketing online, pero no existe una página de servicio ni una tarifa. Para captar «SEO para pymes», «Google Ads para empresas de reformas» o «marketing digital Barcelona» hace falta decidir:

- Si se ofrece como servicio independiente (con precio «desde» o «a medida») o solo como complemento de una web.
- Con qué alcance (SEO técnico, local, contenidos; gestión de campañas).

Cuando se decida, basta con añadir la entrada en `src/data/services.js`: aparecerá sola en el pie, el sitemap, los datos estructurados, llms.txt y las versiones Markdown.

### 3.8 Páginas que **no** hemos creado a propósito

- **Una página por municipio** (Gavà, Sitges, Sant Boi…) con el mismo texto cambiando el nombre: Google las considera «doorway pages» y no aportan. Solo se crearán si hay contenido propio (un proyecto real en esa zona, datos locales).
- **Una página por palabra clave** («diseño de páginas web», «diseño web profesional»…): se cubren como variantes en la página principal de cada servicio.

## 4. Reglas de contenido y on-page

- **Un h1 por página**, que contiene el término principal.
- **Título** ≤ 60 caracteres incluida la marca (el sufijo « | Moira Ordo» ya cuenta). **Descripción** entre 100 y 160 caracteres, con el término principal y una razón para hacer clic. Hay una auditoría automática (ver sección 7).
- **Precios coherentes** en toda la web: diseño desde 199 €, desarrollo desde 299 €, marca desde 199 €. Se leen de `src/data/services.js` y de `src/data/entity.js`; si cambian, se cambian ahí.
- **No inventar datos.** Los casos de `src/data/caseStudies.js` tienen cifras y testimonios **sin validar** (el propio archivo lo advierte); las páginas SEO nuevas no los usan ni en el texto ni en los datos estructurados. Mientras no se validen con cada cliente, tampoco deberían publicarse en la home ni en /proyectos (riesgo de reclamación y de que los asistentes de IA los repitan como hechos).
- **Enlazado interno**: cada servicio enlaza a sus sectores y guías; cada sector enlaza a sus casos, servicios y guías; cada guía enlaza a servicios y sectores; el pie lista sectores, guías, preguntas y páginas locales.
- **Respuestas directas**: cada FAQ responde en 2-3 frases con datos concretos.

## 6. SEO fuera de la web

- **Perfil de Empresa de Google** (categoría «Diseñador de sitios web»), con los mismos nombre, descripción y datos que `src/data/entity.js`.
- **LinkedIn**: página de empresa «Moira Ordo» y perfiles de Aaron y Joselyn enlazados desde la web (ya están en `/sobre-nosotros` como `sameAs`).
- **Directorios** a valorar: directorios de agencias y freelances (Sortlist, Clutch u otros), Páginas Amarillas y directorios locales de Vilanova i la Geltrú / Garraf. Mismo nombre y misma descripción en todos.
- **Enlaces desde los clientes**: pedir que el pie de cada web de cliente enlace a moiraordo.es con texto descriptivo («Diseño y desarrollo: Moira Ordo»). Regia Mare y Vemaro ya incluyen «Desarrollado por MoiraOrdo».
- **Reseñas** en Google de cada cliente al cerrar un proyecto.
- **Redes sociales**: el banco de Instagram ya enlaza a /crm, /proyectos y /contacto con UTM. Cuando existan perfiles públicos, añadirlos a `sameAs` en `src/seo/head.js`.

## 7. Qué está implementado en el código

| Pieza | Dónde |
|---|---|
| Datos de entidad (verificables) | `src/data/entity.js` |
| Sectores, guías, proyectos, ubicaciones, FAQ | `src/data/sectors.js`, `guides.js`, `portfolio.js`, `locations.js`, `faqs.js` |
| Páginas y rutas | `src/pages/Seo/*`, `src/routes.jsx` |
| Datos estructurados enlazados por `@id` | `src/seo/head.js` |
| Markdown, llms.txt, llms-full.txt | `src/seo/markdown.js`, `scripts/prerender.mjs` |
| robots.txt con bots de IA | `scripts/prerender.mjs` |
| Imágenes Open Graph | `scripts/og/generar_og.py` |
| Aviso a buscadores (IndexNow) | `scripts/indexnow.mjs` |

**Auditoría rápida tras cada cambio:** `VERCEL_ENV=production npm run build` y revisar que el resumen del prerender indica `indexable=true`. Los títulos largos, las descripciones fuera de rango, los h1 duplicados, los JSON-LD inválidos y los enlaces internos rotos se pueden comprobar recorriendo `dist/*.html`.
